# قِرْشَك | Qirshak

> "من لا يحسب للقرش، ما يمسك الريال" — مثل تجار العقيلات

**قِرْشَك** مساعد مالي ذكي متعدد الوكلاء (Multi-Agent) يراقب صرفك بدل ما يخليك تسجّله يدوياً. يقرأ كشف حسابك البنكي، يفهم عاداتك، ينبهك باللحظة اللي راح تصرفين فيها بدون تفكير، ويعطيك ميزانية واقعية وودودة — كل هذا عبر فريق من 6 وكلاء ذكاء اصطناعي يتعاونون مع بعض.

**الفكرة الجوهرية:** التسريبات المالية الصغيرة والمتكررة (قهوة بـ20 ريال، اشتراكات منسية) تكلّف أكثر مما يتوقع أغلب الناس. تطبيقات الميزانية التقليدية سلبية — تعرض بيانات بعد ما تصرف الفلوس. قِرْشَك استباقي: يحلل سلوكك ويتواصل معك **قبل** ما تصرف، مو بعده.

---

## المشكلة

- الناس يفقدون تتبع المشتريات الصغيرة المتكررة (قهوة، تطبيقات توصيل) اللي تتجمع لمبلغ شهري كبير
- اشتراكات منسية أو متداخلة تستنزف الفلوس بصمت كل شهر
- تطبيقات الميزانية التقليدية سلبية — تعرض البيانات بعد وقوعها، ما تتدخل باللحظة
- النصائح المالية العامة ("وفّري 20%") ما تعكس سلوك الشخص الفعلي أو دخله الحقيقي

---

## لماذا نظام متعدد الوكلاء (Multi-Agent)؟

كل وكيل يسوي نوع تفكير مختلف يعتمد على مخرجات الوكيل اللي قبله — هذا مو سكربت واحد فيه if/else. التصنيف، اكتشاف الأنماط السلوكية، التنبيه المبني على الوقت، التوقع المستقبلي، النصيحة المالية، وأسلوب العرض — كلها مهارات مختلفة فعلياً مربوطة ببعض بسلسلة، وهذا جوهر تبرير استخدام تنسيق CrewAI بدل لوحة بيانات بسيطة.

## الوكلاء الستة

| # | الوكيل | الدور |
|---|---|---|
| 1 | **Categorizer** | يقرأ كشف الحساب ويصنف كل عملية (قهوة، توصيل، اشتراكات، مواصلات، بقالة، دخل، أخرى) |
| 2 | **Pattern Detective** | يكتشف الأنماط السلوكية العامة — ارتفاع صرف بفئة معينة، فرق أيام الأسبوع عن الإجازة، تكرار غير ملحوظ |
| 3 | **Time-Based Alert Agent** | يتعلم النافذة الزمنية المعتادة للصرف (مثلاً القهوة بين 4-7 عصراً) ويقارن الوقت الحالي وصرف اليوم بهذا النمط لتحديد هل ينبّه المستخدم |
| 4 | **Predictor** | يتوقع مستقبلياً من معدل الصرف الحالي هل المستخدم راح ينفد راتبه قبل نهاية الشهر، وبكم يوم بالضبط |
| 5 | **Budget & Savings Advisor** | يجمع كل التحليلات السابقة بحد إنفاق يومي واقعي لكل فئة وهدف ادخار شهري مبني على السلوك الفعلي |
| 6 | **Tone Agent** | يعيد صياغة التقرير النهائي بأسلوب ودود وخفيف الظل، بدون تغيير أي رقم أو حقيقة |

**ترتيب الاعتماديات:** الوكلاء 1 و2 يشتغلون أولاً ويغذّون الوكلاء 3 و4، واللي بدورهم يغذّون الوكيل 5؛ الوكيل 6 يشتغل أخيراً كمرحلة "إعادة صياغة" بحتة، فما يقدر يُدخل أي خطأ بالبيانات المالية.

```
Categorizer ──┐
              ├──→ Time-Based Alert Agent ──┐
Pattern Detective ┘                          │
                                              ├──→ Budget & Savings Advisor ──→ Tone Agent
              ┌──→ Predictor ────────────────┘
     (يعتمد على 1 + 2)
```

## البنية التقنية (Architecture Summary)

| المعيار | القيمة |
|---|---|
| Framework | CrewAI |
| البنية | Multi-Agent (6 أدوار) |
| الذاكرة | Stateless للوكلاء 1، 2، 4، 5، 6 — Short-Term للوكيل 3 فقط |
| Guardrails الأساسية | Output Schema Validation (JSON)، Confidence Thresholds |
| LLM | Gemini (عبر LiteLLM / تكامل CrewAI المدمج) |
| البيئة | Google Colab |
| البيانات | كشف حساب بنكي وهمي (CSV) للعرض التجريبي |

### الذاكرة بالتفصيل
5 وكلاء (1، 2، 4، 5، 6) عديمة الحالة (Stateless) — كل وكيل يعالج كشف حساب واحد بتنفيذ لحظي واحد بدون حاجة للاحتفاظ بجلسات سابقة بهذا العرض. الوكيل 3 (التنبيه اللحظي) هو الاستثناء: يستخدم ذاكرة قصيرة المدى (Short-Term) للاحتفاظ بإجمالي صرف اليوم كحالة جلسة، ويقارنه بالنمط الزمني المتعلم.

### الـ Guardrails
| الضمانة | أين تُطبّق |
|---|---|
| Output Schema Validation (JSON) | عند كل تسليم بين الوكلاء، خصوصاً Categorizer → Pattern Detective، عشان استجابة مشوّهة ما تكسر السلسلة بصمت |
| Confidence Thresholds | وكيل التنبيه ما يطلق تنبيه إلا لو واثق فعلاً إن صرف اليوم شاذ حقاً، مو بس أعلى من المعدل بشكل هامشي — يمنع تنبيهات مزعجة كاذبة |
| Max Iteration Limits | مفعّلة احترازياً على أي وكيل ممكن يدخل بحلقة، خصوصاً لو أُضيفت أدوات لاحقاً |
| Human-in-the-Loop (HITL) | **غير مستخدمة عمداً** — قِرْشَك استشاري فقط وما يسوي أفعال لا رجعة فيها (ما يلغي اشتراك فعلياً، ما يرسل فلوس)، فبوابة الموافقة غير مطلوبة بالتصميم |

## خطة العرض التجريبي (Demo Plan)

- تشغيل الفريق الكامل على كشف حساب تجريبي مصمم لإظهار أنماط صرف واقعية
- تفعيل التنبيه اللحظي بشكل حي عبر ساعة محاكاة (Simulated Clock) بالواجهة
- عرض التقرير النهائي المُعاد صياغته بأسلوب "قِرْشَك" كلحظة ختامية للعرض
- الاحتفاظ بنسخة احتياطية (سكرين شوت أو مخرجات محفوظة) تحسباً لأي مشكلة تقنية حية
